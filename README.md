# Дашборд мастермайнда — инструкция

Сайт полностью бесплатный, без Telegram-бота и без привязки карты. Вход —
по имени из выпадающего списка и короткому паролю. Есть три роли:

- **Админ** — видит и редактирует всё, отмечает задачи любого участника,
  собирает отчёт дня, меняет настройки.
- **Участник** — видит всё, но редактировать/отмечать может только свой
  профиль (если админ не включил блокировку редактирования в настройках).
- **Гость** — видит всё, ничего не может нажимать/редактировать.

## Шаг 1 — включить вход по паролю в Firebase (один раз, 10 секунд)

Проект уже подключён (`glubina-01`). Зайдите на
https://console.firebase.google.com/project/glubina-01/authentication/providers
и включите провайдер **Email/Password** (просто переключатель вкл/выкл,
сохранить). Больше в консоли Firebase ничего настраивать не нужно, кроме
шага 3 ниже.

## Шаг 2 — создать аккаунты и загрузить задачи (один раз)

Откройте `setup.html` в браузере и нажмите кнопку **«Создать аккаунты и
загрузить данные»**. Скрипт сам создаст 8 аккаунтов (админ, 6 участников,
гость) и один раз скопирует список задач в базу. На той же странице будет
таблица со логинами и паролями — раздайте их участникам.

## Шаг 3 — включить правила безопасности Firestore (важно!)

Пока база открыта в тестовом режиме — это нужно заменить, иначе через
30 дней запись отключится, а до этого момента доступ к записи фактически
открыт всем. Зайдите на
https://console.firebase.google.com/project/glubina-01/firestore/rules
и вставьте содержимое файла `firestore.rules` (он в этой же папке) вместо
текущих правил, нажмите **Publish**.

Эти правила проверяют реального вошедшего пользователя (через Firebase
Auth), а не то, что нарисовано в интерфейсе — то есть это настоящая
защита, не «на глаз».

## Как это работает дальше

- **Вход** — на любой странице сайта сначала показывается экран входа:
  выберите имя из выпадающего списка, введите пароль. Сессия сохраняется
  на устройстве (в том числе в Safari на iPhone) — заново вводить пароль
  не придётся, пока не нажмёте «Выход».
- **Отметка задач** — как раньше: чекбокс или +/− для составных задач.
  Изменения сразу видят все участники.
- **Редактирование задач** — карандаш ✏️ рядом с задачей (виден только
  тем, кому разрешено): можно поменять текст, количество, дедлайн,
  заметку, удалить задачу или добавить новую кнопкой «+ Добавить задачу»
  внизу списка.
- **Сортировка** — задачи с ближайшим дедлайном показываются вверху,
  выполненные на 100% автоматически уходят вниз списка.
- **Отчёт дня** (`report.html`, только админ) — считает разницу между
  началом дня и текущим состоянием: если что-то отметили и потом сняли —
  в отчёте не появится. Готовый текст — кнопка «Скопировать» и вставляете
  в чат вручную. Можно посмотреть отчёт за любую дату через выбор даты.
  Поле «Роль на сегодня» редактируется прямо там же.
- **Настройки** (`settings.html`, только админ) — название турнира, баллы
  за задачу/вовлечение, число участников (для среднего балла), и
  переключатель «запретить участникам редактировать свои задачи».

## Структура файлов

```
site/
├── index.html          — дашборд
├── participant.html    — страница участника (задачи, вовлечение, редактирование)
├── report.html         — отчёт дня (админ)
├── settings.html        — настройки (админ)
├── setup.html            — одноразовое создание аккаунтов (см. Шаг 2)
├── firestore.rules       — правила безопасности для Firebase Console (см. Шаг 3)
├── css/style.css
└── js/
    ├── firebase-config.js  — конфигурация проекта Firebase
    ├── firebase-init.js    — инициализация Firebase (Firestore + Auth)
    ├── data.js               — стартовые задачи и настройки (используются один раз, при первой загрузке в базу)
    ├── credentials.js        — пароли для setup.html (можно удалить после настройки)
    ├── auth.js                — вход, роли, навигация
    ├── store.js                — работа с Firestore: участники/задачи/прогресс/события
    ├── app.js                   — дашборд и страница участника
    ├── report.js                 — отчёт дня
    └── setup.js                   — одноразовое создание аккаунтов и загрузка данных
```

## Баллы и вовлечение

Баллы и минимальная планка вовлечения теперь редактируются на странице
`settings.html` (баллы) и — для планки конкретного участника — пока
только через саму базу Firestore (`participants/{id}.engagementMin`);
если нужно сделать это редактируемым на сайте, скажите — легко добавить.
