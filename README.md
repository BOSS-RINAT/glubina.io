# Дашборд мастермайнда — инструкция

Сайт полностью бесплатный, без Telegram-бота и без привязки карты. Вход —
по имени из выпадающего списка и короткому паролю. Есть три роли:

- **Админ** — видит и редактирует всё, отмечает задачи любого участника,
  собирает отчёт дня, смотрит журнал действий, меняет настройки.
- **Участник** — видит всё, но редактировать/отмечать может только свой
  профиль (если админ не включил блокировку редактирования в настройках).
- **Гость** — видит всё, ничего не может нажимать/редактировать.

## ⚠️ Сначала — важное про безопасность

Файл `js/credentials.js` содержит пароли всех аккаунтов открытым текстом.
Он нужен только один раз — для страницы `setup.html`, которая создаёт
аккаунты. **После того как аккаунты созданы:**

1. Удалите `js/credentials.js` и `setup.html` + `js/setup.js` из репозитория
   на GitHub (или откуда бы вы ни раздавали сайт).
2. Если репозиторий когда-либо был публичным с этими файлами внутри —
   на всякий случай смените пароли: Firebase Console → Authentication →
   Users → выбрать пользователя → **Reset password** (или удалить и
   создать заново через `setup.html`, пока он ещё не удалён).

## Шаг 1 — включить вход по паролю в Firebase (один раз, 10 секунд)

Зайдите в свой проект на https://console.firebase.google.com →
Authentication → Sign-in method → включите провайдер **Email/Password**.

## Шаг 2 — создать аккаунты и загрузить задачи (один раз)

Откройте `setup.html` в браузере и нажмите кнопку **«Создать аккаунты и
загрузить данные»**. Скрипт сам создаст 8 аккаунтов (админ, 6 участников,
гость) и один раз скопирует список задач в базу. Логины и пароли — в
таблице на той же странице (берутся из `js/credentials.js`).

## Шаг 3 — включить правила безопасности Firestore (важно!)

Зайдите в Firebase Console → Firestore Database → Rules и вставьте
содержимое файла `firestore.rules` (он в этой же папке) вместо текущих
правил, нажмите **Publish**. Эти правила проверяют реального вошедшего
пользователя через Firebase Auth — это настоящая защита, не «на глаз».

## Как это работает

- **Вход** — выберите имя из выпадающего списка, введите пароль. Сессия
  сохраняется на устройстве (в том числе в Safari на iPhone) — заново
  вводить пароль не придётся, пока не нажмёте «Выход».
- **Отметка задач** — чекбокс или +/− для составных задач. Изменения сразу
  видят все участники.
- **Редактирование задач** — карандаш ✏️ рядом с задачей (виден только
  тем, кому разрешено): текст, количество, дедлайн, заметка; удаление и
  добавление новой задачи кнопкой «+ Добавить задачу» внизу списка.
- **Сортировка** — задачи с ближайшим дедлайном показываются вверху,
  выполненные на 100% автоматически уходят вниз списка.
- **Отчёт дня** (`report.html`, только админ) — считает разницу между
  началом дня и текущим состоянием: если что-то отметили и потом сняли —
  в отчёте не появится. Готовый текст — кнопка «Скопировать», вставляете
  в чат вручную. Можно посмотреть отчёт за любую дату.
- **Журнал действий** (`journal.html`, только админ) — кто, что и когда
  нажал (в том числе снял галочку), с возможностью отменить конкретное
  действие. Плюс блок «🔥 Горящие дедлайны» на выбранную дату по всем
  участникам сразу.
- **Графики динамики** (`charts.html`) — три графика (баллы / выполненные
  цели / вовлечение) по дням, каждый можно скрыть отдельно или все разом,
  фильтр по периоду (7/30 дней, всё время, свой диапазон) и по
  участникам. Открывается по ссылке в меню или кликом на любую из трёх
  плиток статистики на дашборде.
- **Игра** (`game.html`) — 2048, чтобы позалипать между задачами. Свайпы
  на телефоне, стрелки на компьютере, рекорд сохраняется в браузере.
- **Настройки** (`settings.html`, только админ) — название турнира, баллы
  за задачу/вовлечение, число участников (для среднего балла),
  минимальная планка вовлечения для каждого участника, и переключатель
  «запретить участникам редактировать свои задачи».

## Что нового (последнее обновление)

- **Шаговые задачи** — в форме редактирования задачи теперь явный
  переключатель «Пошаговая задача»: включили — появляется поле
  «Количество шагов», задача превращается в счётчик с +/−.
- **Удаление задач** — кнопка «Удалить» в той же форме (было и раньше,
  проверено ещё раз).
- **Динамика с вчера** — на дашборде под «Прогресс группы» и «Вовлечение
  группы» появилась маленькая строка: ▲ +5% с вчера (зелёным),
  ▼ −2% (красным) или • без изменений. Сравнение идёт с состоянием на
  конец предыдущего дня по московскому времени.
- **История баллов** (`points-history.html`, видна всем) — открывается
  кликом на плитку «Суммарный балл группы». Живой список: кто и за что
  получил баллы прямо сейчас. Если задачу сняли — строка исчезает сама,
  список не хранится отдельно, а каждый раз пересчитывается из текущего
  состояния.
- **Настройки → ручная корректировка баланса** — число (можно
  отрицательное), которое прибавляется к общему баллу команды на
  дашборде и в истории баллов, не трогая баллы конкретных участников в
  рейтинге. Удобно, если нужно сдвинуть точку отсчёта.
- **Настройки → баллы за шаги** — переключатель «Начислять баллы за
  частичное выполнение шаговых задач» (по умолчанию выключен — баллы
  дают только полностью закрытые цели). Так как баллы каждый раз
  считаются заново из текущего состояния (нигде не накапливаются как
  отдельное число), выключение переключателя мгновенно и без каких-либо
  дополнительных действий убирает баллы за шаги везде на сайте.

**Важная техническая деталь:** переключатель «баллы за шаги» и ручная
корректировка сейчас учитываются на дашборде, в рейтинге участников и в
истории баллов. На графике «Баллы» (`charts.html`) и в отчёте дня
(`report.html`) пока используется прежняя упрощённая логика (баллы только
за полностью закрытые цели, без ручной корректировки) — если нужно
привести всё к единому виду, скажите, это отдельная, более объёмная
доработка (там баллы считаются по историческим точкам во времени, а не
по текущему состоянию).

## Баллы и вовлечение

Баллы за задачу/вовлечение и минимальная планка вовлечения каждого
участника редактируются на странице `settings.html`.

## Как устроены графики технически (если интересно / для отладки)

Каждое изменение (отметка задачи, вовлечение, редактирование задачи)
пишется в коллекцию `events` с датой по московскому времени. Страница
графиков читает всю эту историю, группирует по дню и строит нарастающий
итог: «сколько задач полностью закрыто» и «сколько вовлечений» на каждый
день, умножая на текущие баллы из настроек. Если баллы за задачу/вовлечение
менялись со временем в настройках — график всё равно считает по
*текущим* баллам для всей истории (упрощение, чтобы не усложнять систему
хранением истории изменений самих настроек).
