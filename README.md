# Дашборд мастермайнда — инструкция по запуску

Это обычный статический сайт (HTML/CSS/JS), никакой установки не требуется.

По умолчанию сайт работает в **локальном режиме**: прогресс хранится в
браузере (localStorage) только на том устройстве, где его отмечали. Чтобы
**все участники видели общий прогресс друг друга в реальном времени**,
подключите бесплатный Firebase — это займёт 5 минут, см. раздел
[«Общий доступ через Firebase»](#общий-доступ-через-firebase) ниже.

## Как запустить

**Способ 1 — просто открыть файл.**
Дважды кликните на `index.html` — сайт откроется в браузере. Обычно этого
достаточно, особенно если уже подключён Firebase (см. ниже).

**Способ 2 — через локальный сервер** (если вдруг браузер ограничивает
работу без Firebase, в локальном режиме через `file://`):
```bash
cd путь/до/папки/site
python3 -m http.server 8000
```
и откройте http://localhost:8000. Или, если установлен Node.js:
```bash
npx serve .
```

Каждый участник может открывать сайт **на своём собственном компьютере** —
это не мешает общей синхронизации через Firebase, она работает через
интернет, а не через локальную сеть.

## Общий доступ через Firebase

1. Откройте https://console.firebase.google.com → **Add project**.
   Название любое, например `mastermind-dashboard`. Google Analytics
   подключать не обязательно.
2. В проекте слева: **Build → Firestore Database → Create database**.
   Выберите любой регион и режим **Start in test mode** (открытый доступ на
   30 дней — для небольшой закрытой группы этого достаточно; как продлить
   или ограничить доступ — см. раздел ниже про правила безопасности).
3. На главной странице проекта нажмите значок **«</>»** (Web app), задайте
   любое имя приложения, нажмите **Register app**. Firebase покажет объект
   `firebaseConfig` — скопируйте его.
4. Откройте `js/firebase-config.js` и замените объект-заглушку на
   скопированный. Сохраните файл.
5. Откройте `index.html` — если всё верно, вверху появится
   «🟢 Синхронизировано со всеми участниками».
6. Разошлите папку `site` (со уже заполненным `firebase-config.js`) всем
   участникам, либо разместите её на любом бесплатном статическом хостинге
   (например Firebase Hosting, Netlify, GitHub Pages) и разошлите ссылку.
   Все, кто откроет сайт с этим же `firebase-config.js`, будут видеть
   и менять один и тот же общий прогресс.

**Если Firebase недоступен** (нет интернета, неверный конфиг) — сайт
автоматически откатится в локальный режим, ничего не сломается.

### Про безопасность правил Firestore

В тестовом режиме доступ на чтение/запись открыт всем, у кого есть ссылка
на конфиг (то есть всем, кому вы отправили папку/ссылку) — без пароля.
Для закрытой группы из нескольких доверенных людей это обычно приемлемо.
Через 30 дней тестовый режим отключит запись — тогда в Firebase Console →
Firestore Database → **Rules** замените правила на:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /mastermind/progress {
      allow read, write: if true;
    }
  }
}
```
(это продлевает открытый доступ бессрочно — подходит, если делиться
конфигом вы будете только с участниками мастермайнда).

## Структура файлов

```
site/
├── index.html              — дашборд (общая статистика + рейтинг участников)
├── participant.html        — страница задач конкретного участника
├── css/style.css           — стили
├── js/data.js               — список участников и задач (можно редактировать)
├── js/firebase-config.js    — конфигурация Firebase (по умолчанию заглушка)
└── js/app.js                 — логика приложения
```

## Как редактировать список задач

Откройте `js/data.js` — там простой список объектов. Для каждой задачи:
- `qty` — сколько единиц нужно выполнить (например, 5 экскурсий → `qty: 5`).
  Обычная задача без счётчика → `qty: 1`.
- `deadline` — дата в формате `'YYYY-MM-DD'` или `null`, если срока нет.
- `note` — необязательный комментарий-пояснение.

## Индикация дедлайнов

- 🔴 Красный — срок прошёл, задача не выполнена.
- 🟡 Жёлтый — осталось 5 дней или меньше (показывается независимо и может
  быть вместе с зелёным, если по остальным задачам всё в порядке).
- Обычный — срок ещё не горит.
- ✅ Зелёный «всё в графике» — нет ни одной просроченной задачи.

Многосоставные задачи (например, 3 из 5 экскурсий) засчитываются
пропорционально в процент выполнения, а полностью закрытые подсвечиваются
зелёным.

## Как отмечать выполнение

- **Обычная задача** — нажмите на чекбокс или на текст задачи.
- **Составная задача** (например, «5 экскурсий») — используйте кнопки **+ / −**
  под задачей, чтобы прибавлять по одной. Каждая единица сразу добавляет
  свою долю в процент выполнения (1/5 = 20% и т.д.). Клик по тексту задачи
  сразу отмечает её как полностью выполненную (повторный клик — сбрасывает).

## Баллы и рейтинг

- **2 балла** — за каждую полностью выполненную задачу (не важно, простая
  она или составная — засчитывается сам факт закрытия задачи).
- **3 балла** — за каждого вовлечённого человека (см. ниже).
- Наверху дашборда отдельными плитками показаны: общий % выполнения задач
  группой, общее вовлечение группы и суммарный балл группы.
- Участники в списке «Рейтинг участников» отсортированы по баллам:
  топ-3 отмечены медалями 🥇🥈🥉, у остальных — номер места. Стиль карточек
  одинаковый для всех — отличаются только медаль/номер места.

## Вовлечение

Отдельная метрика на странице участника (не входит в список задач).
У каждого участника есть **минимальная планка** (её нужно достичь), но
максимума нет — вовлекать можно сколько угодно людей сверх нормы:

- Ирина, Игорь, Виктория, Нурсултан, Тагир — планка **1**
- Евгений — планка **5**

Планку легко изменить в `js/data.js` — поле `engagementMin` у каждого
участника.
